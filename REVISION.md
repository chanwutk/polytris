# Revision measurements (SIGMOD '27 #965, major revision)

Data collected for the revision lives in three top-level directories.

| Directory | Contents | Runs |
| --- | --- | --- |
| `measurements-gpu/` | One Python script per long-running GPU job the revision needs (retraining for timing, rerunning detection on packed canvases, ...). It writes into the cache, like the pipeline stages. | On ace, in a tmux session |
| `measurements/` | One Python script per measurement. It reads existing data (cache, tradeoff tables, outputs of `measurements-gpu/`) and aggregates it. | On ace, minutes at most |
| `measurements-results/` | Outputs of `measurements/`, committed to git. | Pulled back from ace |

## Conventions

- `measurements/X.py` writes only into `measurements-results/X/`, a directory holding one or more JSON files. `measurements.common.results_dir(__file__)` returns that directory, so the name always matches the script.
- `X` starts with the review item it answers, as in the response letter and the checklists: `r1o2_count_query.py`, `r9o2_preparation_cost.py`. Shared helpers live in `measurements/common.py`.
- A `measurements/X.py` that depends on a `measurements-gpu/Y.py` says so in its docstring and in the table below, and fails with a clear error when Y's outputs are missing. For example, R1.O4's accuracy script reads the canvas detections that a GPU script reruns, and R9.O2's preparation-cost script reads the training times that a GPU script records.
- Every `measurements/X.py` has tests in `tests/test_measurements_X.py` covering its rules and edge cases.
- Scripts follow `AGENTS.md`: comments on every operation, `parse_args` near the top without comments.

```sh
# Mac: push code (measurements/ and measurements-gpu/ are in configs/sync.yaml).

# ace: run tests, then a measurement, inside the polyis container (/polyis is this checkout).

# Mac: pull results back. measurements-results/ is not in sync.yaml, so ./sync never overwrites newer results on ace.

```

## Findings and decision status

Found while measuring; resolutions and remaining limitations are recorded below.

1. **Tolerance labels (Table 2, Fig. 7, R1.O5).** The values listed as the mistrack-rate tolerance M (none, 0.4, 0.6, 0.8) are the code's accuracy threshold t; p016 keeps a gap when accuracy >= t, i.e. MissRate <= 1 - t. The validated tolerances are M = 0.2, 0.4, 0.6, and Fig. 7's "M = 0.8" panel is the strictest setting (MissRate <= 0.2). See `measurements-results/r1o5_gap_tolerance/`.
2. **Accuracy-matched comparison wording, resolved by author decision.** Retain p203's original algorithm and numbers. Section 7 now explicitly applies the 5%/10% bound to Tetris and compares with selected Pareto-optimal prior configurations whose HOTA is no higher than Tetris's. Prior configurations can miss the loss bound; the alternative shared-bound comparison is not used. The submitted abstract and original introduction/conclusion wording are preserved per the author's follow-up. See `r7o1_hota_matched_speedup`.
3. **Timing boundary (R1.O3), verified independently by two read-only passes.** p121's throughput counts the reference's per-frame video decode (1.4-2.2% of its time) but not Tetris's decoding (p020's recorded whole-video read is dropped; p030's per-configuration decode is untimed), and it counts Tetris's canvas reads (p040 `read`, 4-6% of Tetris's time), so "excluding disk I/O" (07_eval.tex lines 157-158, wip/r1o3.tex) is inaccurate on both sides. Tetris's speedup over the reference by boundary:

   | Boundary | Amsterdam | CalDoT1 | CalDoT2 | B3D |
   | --- | --- | --- | --- | --- |
   | Paper (p121) | 68.8x | 23.6x | 4.7x | 17.3-29.1x |
   | Decode excluded on both sides | 67.5x | 23.1x | 4.6x | 17.0-28.7x |
   | One decode per side at the reference's measured cost | 30.1x | 15.6x | 4.3x | 13.8-20.4x |
   | Same, without Tetris's canvas reads | 30.9x | 16.2x | 4.5x | 14.4-21.0x |
   | Wall clock of the staged prototype | 5.9x | 5.5x | 2.7x | 5.5-6.4x |

   The wall-clock row charges Tetris two decodes, an avoidable channel-flip copy in p020 (7.4 vs about 1.5 ms per frame), inter-stage file I/O, and worker contention, so it is an upper bound on Tetris's cost, not a like-for-like comparison. Either charge Tetris one decode or drop decoding from the reference, and drop or disclose canvas reads. Unverified confounds: the reference detects at batch 1 and p040 at batch 4, and the two ran six weeks apart under different GPU load.
4. **R9.O1 "same videos and hardware".** Resolved by `r9o1_matched_timing` (same frames, one idle Quadro RTX 6000, Xeon Gold 6248). The ratio depends on batching and boundary, so the response should name them: about 27-38x as deployed, 21-25x at equal batch size, and 9-12x if p020's RGB copy (2-5 ms per frame, paid only by Tetris) is counted. Host placement alone moved the as-deployed ratio by up to 22% (unpinned 31-49x).
5. **CalDoT2 validation cache.** A 2026-05-29 single-configuration rerun deleted the 022-060 outputs of 89 of 90 configurations for va00-va09 (890 missing pruning runs), so CalDoT2's Pareto selection cannot be re-derived from the cache.
6. **p022 binarization, restored to the cache-compatible rule.** p022 now keeps score >= floor(r x 255), as the April 2026 cache did. A regression test checks all 256 quantized scores at six thresholds, including both endpoints, at the actual grouping input. No cached outputs or reported numbers are changed. Historical audit key `current` still denotes score > r x 255 (median -0.1% variables, up to -5.4%), with its meaning documented. Separately, p022's `--time-limit` help still says 0.5 s; the effective budget is 0.1 s.
7. **Section 6.2 TotalA.** The text says associations are counted at the native rate; p016 counts them at the frames each gap samples.
8. **02_background.tex lines 168-169** pair the `\mistrackStdCaldottwo...` macro with the name CalDoT1.
9. **LEAP native-query scope, resolved by author decision.** Use one merged vehicle class; car/truck/bus comparisons are not required. The original lack of class labels no longer blocks this workload.
10. **p012** removes `always_relevant/` for each video while 20 workers write to it (pipeline bug, not fixed).
11. **LEAP's B3D frame base.** LEAP's B3D exports run 1.39-1.49x the clip length, the B3D input videos in LEAP's workspace are 29 FPS copies with about twice our frames, and LEAP's per-frame counts on B3D1, B3D2, and B3D4 correlate best with ground truth at time scales 0.5, 0.85, and 0.8. If LEAP ran on the 29 FPS copies, its B3D tracks are misaligned with our 15 FPS clips and its B3D HOTA and query numbers are not comparable. Confirming needs the scored run's inputs, which are not on ace (`r1o2_leap_hota_conversion`).
   **Resolved (2026-11-03):** the later rerun (`r1o2_leap_otif_rerun`, evidence `leap_rerun.json`) shows LEAP's B3D test and train clips are byte-identical to our 15 FPS clips (`video_identity`), and its raw observations align with ground truth at lag 0, scale 1.0 (`frame_base`: 97-99.9% matched, mean IoU 0.87-0.91). LEAP's B3D clock is correct.
12. **TrackEval scoring window (all systems).** TrackEval's HOTA, CLEAR, and Identity metrics iterate zip(ground truth frames, tracker frames), and each side's frame list ends at that file's last row, so ground-truth boxes after a system's last output row are never counted as misses (and tracker boxes after the ground truth's last row are never counted as false positives). Unscored ground truth: Tetris median 0.04% (up to 3.4%), OTIF up to 4.7%, LEAP up to 5.4%, reference 0.05% or less. Padding both sides to the clip lowers HOTA by at most 0.0074 (Tetris), 0.0135 (OTIF), 0.0027 (LEAP), 0.0006 (reference), and moves two quoted ranges: Tetris over the reference at 5% 4.7-68.8x to 6.6-68.8x (CalDoT2, a 1e-5 near-tie) and at 10% 10.4-91.2x to 10.4-73.1x (Amsterdam; Tetris over OTIF there 5.8x to 4.6x). ## LEAP sampling and reconstruction diagnosis (2026-10-31)

Read-only CPU analysis of the saved detector-matched CalDoT/Amsterdam runs and the saved B3D reruns.
No detector, sampler, tracker, baseline configuration, cache, or paper result was changed.
The script is `measurements/r1o2_leap_sampling_diagnostics.py`; its companion `r1o2_leap_sampling_plots.py` generates inspection-only Altair PDFs/HTML and `summary.csv`.
Results are in `measurements-results/r1o2_leap_sampling_diagnostics/`.

- **Sampling target.** LEAP's paper targets sampling near 2-frame optimality, using predicted exits to choose the next frame. It also explicitly handles objects observed only once and refines patterns/intervals for changing traffic. Thus neither “every object is guaranteed two observations” nor “LEAP assumes identical travel times” is accurate. Reference: https://doi.org/10.1145/3639274, Sections 3.2 and 4.3-4.5. The runtime copy uses min/max gap clamps, with no guarantee of two linked observations. Runtime source hashes and rule locations are in `code_provenance.json`.
- **Pattern/configuration incompatibility.** Eligible/loaded patterns are CalDoT1 2/7, CalDoT2 1/3, Amsterdam 0/33, B3D1 11/19, B3D2 3/16, B3D3 0/4, B3D4 7/11. The runtime excludes a pattern if either endpoint misses its configured entry/exit region. Amsterdam retains the same two regions as CalDoT1 despite a different scene/resolution. The incoming CalDoT2 pattern starts at y=244, just outside its region beginning at y=248. With no eligible patterns, `get_point_update` always produces fallback `[66, 66]`, using a fixed pattern and point index 60. All Amsterdam/B3D3 predicted IDs end with this fallback. See `pattern_regions.pdf` and per-pattern endpoint coordinates in `results.json`. This is a setup/library-coverage problem, not evidence that roundabouts have no motion patterns.
- **One observation per predicted ID is not one sampling opportunity per physical object.** On B3D3, 296 annotated tracks have multiple matched observations, and all 296 use multiple LEAP IDs. Only 18/1,016 matched consecutive-frame pairs retain an ID (1.8%). All 998 pairs failing the stationary-overlap rule lose the ID; all 18 satisfying it retain the ID. This supports association failure after sampling, rather than claiming those vehicles were each sampled once. Matching here is a diagnostic one-to-one IoU>=0.5 assignment, never an input to the baseline.
- **CalDoT1 versus CalDoT2 versus Amsterdam.** Overall ID continuity is 75.7%, 37.7%, and 77.6%. The aggregate hides scene composition: 921/953 successful CalDoT1 links and all 1,073 Amsterdam links satisfy the stationary-overlap rule; CalDoT2 has no matched pair satisfying that rule. Among pairs failing it, continuity is 9.9%, 37.7%, and 0%, respectively. It would therefore be misleading to attribute CalDoT1's higher overall score to superior tracking of curved moving trajectories.
- **Geometry diagnostic.** Using true identities and true boxes at the actual sampled times, linear interpolation achieves IoU>=0.5 on 84.3% of bracketed CalDoT1 boxes, 33.2% of CalDoT2, and 94.6% of Amsterdam. Ideal bracketing covers 73.7%, 42.8%, and 70.7% of all annotated boxes, respectively. CalDoT2 has smaller perpendicular path deviation, but a larger along-line timing error relative to box size. Keeping true box sizes barely improves its interpolation (33.6% above IoU 0.5), whereas keeping true centers and interpolating sizes gives 91.1%. Thus projected center motion, not just box scaling or road curvature, matters. A selected, visually inspected CalDoT2 case (`caldot2-example/`) has accurately detected endpoints four seconds apart but zero midpoint box overlap under linear interpolation; its native-frame motion has no abrupt identity jump. Perspective is a plausible explanation for the nonuniform image-space progress, not a separately measured causal effect.
- **Time in view.** `time_in_view.pdf` and `summary.csv` quantify the variation. For complete annotated tracks lasting at least one second, B3D1/2/3/4 have median spans 12.0/8.5/13.4/9.3 seconds and respective 10th-90th percentile ranges 1.4-20.4, 1.2-24.3, 2.0-24.3, and 1.5-20.5 seconds. These are automatic annotated spans, not verified physical dwell times. Boundary-censored tracks and sub-second fragments are reported separately in `results.json`; 37 B3D3 boxes past decoded clip ends are excluded only from this diagnosis. The existing benchmark scorer and annotations are untouched. Every inspected test clip is actually 15 FPS (`video_fps.json`).

Validation: four diagnostic tests pass, covering one-to-one matching, IoU boundaries, sampling exposure versus identity fragmentation, straight-line interpolation, and missing pattern-export frames. Each dataset also checks identity-link denominator agreement, fixed-library hash consistency, and all-fallback behavior when no pattern is eligible. Plots are inspection artifacts and are not included in the manuscript.

Before making a causal claim about LEAP's motion model, correct/audit the dataset-specific region definitions and pattern coverage, then rerun the affected LEAP configurations. Keep the current reported numbers unchanged until that comparison is reviewed. In particular, do not equate “unsignalized” with “no patterns,” or use one-observation predicted IDs alone to claim that physical objects were not sampled twice.
